Make a GitHub account & your first repo.

Cost · $0 Needed · an email, a username you'll like Difficulty · gentle

Now we make your GitHub account and create your first repository. By the end of this chapter you'll own a real, working corner of the internet where projects can live and grow.

Step 1 — make the account

  1. Go to github.com.
  2. Click Sign up.
  3. Pick a username you'll be happy with. It shows up in URLs, like github.com/your-name. Tip: simple is better than clever, and you can't easily change it later.
  4. Use the same email you used for Claude in Chapter 01. This makes things smoother later.
  5. Verify your email.
  6. Pick the free plan. GitHub's free tier is generous and is all you'll need.

Step 2 — make your first repo

Once you're signed in, look for a green New button — or click the + icon in the top right corner, then New repository.

You'll be asked a few questions:

  • Repository name: something you'll recognize. For practice, try hello-claude or my-first-repo.
  • Description: a short sentence about what's in here. "A place to practice with Claude" is perfectly fine.
  • Public or Private: see the next section — this one deserves a moment.
  • Initialize this repository with a README: check this box. A README is a starter file that explains what the project is.

Hit Create repository.

Public vs Private — when to pick which

A lot of people new to GitHub make everything private out of caution. That's totally fine. But here's the honest framing:

  • Public — anyone in the world can find and read your repo. (They can't change it without your permission.) Good for: learning out loud, sharing with friends, open-source contributions, building a portfolio, asking strangers for help.
  • Private — visible only to you and people you invite. Good for: anything with passwords or personal information, work secrets, drafts you're not ready to show.

Most code on GitHub is public. There's a long, beautiful tradition of learning out loud — and a saying that if you're not embarrassed about your early work, you waited too long to share it.

For practice projects, public is great. For anything with secrets, always private. You can also change a repo's visibility later from its Settings page.

What you just made

You now have a folder on GitHub's servers that:

  • Tracks every change you ever make to it (forever)
  • Has its own URL: github.com/your-username/hello-claude
  • Can be linked to Claude Code in Chapter 06, so Claude can read and edit the files for you
Try this now Click around the repo you just made. Notice the README file in the file list. Click on it. Try the pencil icon to make a tiny edit — change "Hello" to "Hello, world." Scroll down, write a short commit message ("update greeting"), hit Commit changes. Congratulations — you just made your first commit.

A side trip — what's a "commit"?

A commit is a saved snapshot of your project at a specific moment, along with a short note describing what you changed. GitHub keeps every commit, forever. The list of your commits is the story of your project.

You don't need to memorize this. Claude Code will make commits for you. You just need to know that the word exists and roughly what it means.

One reassurance: you can't really break GitHub. Click anything. Explore. The undo button has a long memory.
